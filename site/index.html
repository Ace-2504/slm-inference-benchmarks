The lesson in both: "faster" isn't one fixed number — it depends on how you use the machine. The KV cache just saves the model from redoing work it already did, and it helps more the more people you serve at the same time. Speculative decoding lets a small, quick model guess the next few words while the big model only checks the guesses — so it saves time only when the guesses are usually right. Ask for something predictable, like a list of numbers, and the guessing works; ask for a poem, and it doesn't.
Section 2 · serving many streams at once
Continuous batching · offline study

Static batching runs a whole batch to completion before admitting anyone new, so short requests sit idle in their slot. Continuous batching refills a slot the instant it frees up. (Run offline — sustained many-request load isn't reasonable to serve live.)

PagedAttention · offline study

Naive serving reserves a full max-length block of KV memory per sequence up front — mostly empty. Paging hands out small fixed blocks only as tokens are actually generated, so far more sequences fit in the same memory.

Measured wasted KV memory vs block size: the paged line stays far below the naive reserve-max (dashed) across every block size.

–more sequences fit in the same memory
The lesson in both: a fast chip is wasted if it's sitting idle or half-empty. Continuous batching fixes wasted time — the moment one request finishes, the next one takes its seat instead of leaving it empty while a long request runs on. PagedAttention fixes wasted space — it stops setting aside room for long answers that almost never come, and hands out memory only as it's actually needed. One keeps the chip busy, the other keeps its memory full, and both let the very same card serve many more people at once.
