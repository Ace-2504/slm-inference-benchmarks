The KV cache, switched off

One decode loop keeps the cache and feeds one token per step; the other recomputes the whole growing sequence every step. At batch 1 the uncached loop does 60× more arithmetic yet finishes in the same time — the GPU is memory-bound and idle. The gap opens only as the batch fills the compute units.

Speculative decoding, live

A small draft proposes k tokens; the 7B target verifies them in one pass and keeps the longest correct prefix. Exact, modulo bf16 near-ties. The payoff swings hard by prompt type — the draft here is launch-bound, so it doesn't always win.

Continuous batching & PagedAttention

Held offline — sustained multi-request GPU load isn't reasonable to serve to a visitor — but measured the same way. Plots and numbers are in the report and repo.

How it runs

Experiment 1 uses a 125M-class model; experiment 2 pairs a 7B target with a 0.5B draft, all bf16 on an L4 via Modal. Every timer synchronises, warms up and repeats — validated by an 8-test gauntlet showing an un-synchronised matmul under-reports its time by ~330×. Both sides are checked for identical tokens first.
