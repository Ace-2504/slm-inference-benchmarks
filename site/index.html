Four inference tricks, measured — not quoted.

One pipeline, four controlled experiments on an NVIDIA L4. Each toggles exactly one thing, and both sides are checked to emit the same tokens before any speedup is claimed. Press a button to run experiments 1 & 2 live; the numbers below are the recorded run.

Experiment 1

With and without the KV cache

Two decode loops over the same model: one keeps the cache and feeds one token per step; the other recomputes the whole growing sequence every step. Sweep the batch size — at batch 1 the uncached loop does 60× more arithmetic yet finishes in the same time (the GPU is memory-bound and idle). The gap only opens as the batch fills the compute units.

Experiment 2

With and without speculative decoding

A small draft model proposes k tokens; the big target verifies them in one forward pass and keeps the longest correct prefix. It is exact (modulo bf16 near-ties). The catch: the draft here is kernel-launch-bound, so c = draft/target step = 0.43, and the payoff swings hugely by prompt type. Pick one and watch who produced each token.

Experiments 3 & 4 · offline

Continuous batching & PagedAttention

Held offline (sustained multi-request GPU load isn't reasonable to serve to a visitor), but measured the same way — see the report and repo for the plots.

How it runs

Experiment 1 uses a 125M-class model; experiment 2 pairs Qwen2.5-7B-Instruct (target) with Qwen2.5-0.5B-Instruct (draft), all bf16 on an L4 via Modal. Every timer calls cuda.synchronize(), warms up, and repeats — validated by an 8-test gauntlet that shows an un-synchronised matmul under-reports its time by ~330×. Both sides of every comparison are checked for identical tokens before any speedup is reported.
